# Shot Workspace

Shot Workspace is an optional film authoring mode. Director Agent remains available as a separate project setting.

## Workflow

1. Add a shot and edit its brief, duration and camera fields.
2. Select Library references and add binding notes. New shots inherit the immediately preceding shot's image reference bindings, including selected files, picture indices and notes. Bindings can then be edited independently; the first shot starts without references.
3. Use the collapsible **Description assistant** to discuss filming or create/revise a description. Shot discussion, amendments and inline **Refine** always receive the current shot's selected reference descriptions and binding notes, plus the immediately previous shot description (up to 2,000 characters, marked when truncated). Previous-shot text is authored continuity context, not evidence of a generated video's ending. A small semantic intent decision distinguishes editing, discussion and unrelated chat; there is no exact-phrase gate. Discussion may retain one recent user/assistant pair (600 characters each), and loads the next shot description only when needed. Greetings and unrelated chat use only the latest request and current description for routing. No mode receives image pixels, generation prompts or the full project/chat history. Conversation records and latest operation timings are stored separately per shot and restored across navigation, refreshes and service restarts; saving them does not expand model context. Discussion does not edit shots. Explicit description edits and inline Refine are validated and saved by the backend before the UI acknowledges success; no additional confirmation or Save is needed. Submitted descriptions and saved versions appear in the per-shot conversation. **Apply suggestion** explicitly requests a description change; **Undo description change** restores the previous local draft. Manual brief edits still have their own Save action; prompt writing is separate.
4. Write the prompt. The writer receives the current shot, selected Library descriptions and saved continuation settings; it does not receive chat history or inspect image pixels.
5. Review the prompt and generate video. Desktop places output beside the brief; mobile places video generation and output below it on the same Shots page, without a separate Production tab. Editing a draft immediately marks an existing prompt out of date; saved reference changes trigger a new prompt check. **Clear** clears the local brief, dialogue and camera fields while retaining references; **Save** persists the empty brief. **Write prompt** saves the current edits before writing. During preparation and writing, progress replaces stale-prompt warnings; if writing fails or is cancelled, unresolved warnings return. The previous saved prompt remains available until a new candidate passes validation.

Use one dialogue cue per line: `Speaker [Language]: exact spoken words`. Speaker attribution and wording are retained in the generated speech contract.

Five seconds is only the initial duration. The assistant can suggest timing from the action, dialogue delivery and camera movement, re-estimating timing independently on each refinement rather than treating the current value as a target and honoring explicit timing requests. Applying its brief draft updates the duration field too; Undo restores the previous draft duration, and users can manually override it. Prompt edits that change timing save the revised duration before writing. Changing duration makes an existing prompt stale. Suggestions must remain positive and at most 120 seconds.

The assistant also accepts explicit requests to write or revise the six-section prompt. It saves the current brief before running the same durable, cancellable writer used by **Write prompt**. Requests that change shot action or camera intent first produce a matching brief update; wording-only prompt edits leave the brief intact. The writer receives the previous prompt and the current edit request, without replaying the conversation or re-reading images. Questions about prompts do not trigger writing. Failed or cancelled writing keeps the previous prompt, and any already saved brief remains saved.

Open **Voice references** in the shot to **Import voice**, select an imported sample to link it immediately. Removing a voice is also saved immediately; optional speaker/direction edits save on leaving the field. Failed changes restore the last confirmed bindings and show an error. The writer automatically matches a unique character or dialogue speaker from the asset name or original filename. An optional Speaker override and voice direction remain under the collapsed voice settings. Ambiguous or unmatched samples require a clearer name or an explicit override before writing. Linked samples can be previewed. Up to three H3-ready voices may be linked, with a combined duration of at most 15 seconds. Voice bindings and saved asset descriptions are supplied to the writer; changing bindings, descriptions or audio content invalidates its prompt. Rewrite after changing voices. Native source audio cannot be combined with these voice bindings. Save unsaved brief edits before changing voices.

Changing a brief, selected reference, Library description or continuation intent invalidates the saved prompt. Switching the generated variation or output of the same continuation source does not require rewriting. Video availability, resolution and frame compatibility are still checked before generation. Rule-based checks catch missing sections, reference indices and malformed tags; they do not certify visual quality.

## Library

Assets opens Library only. Import an image, enter its name and optional description, and click the wand to obtain an editable description suggestion. The same action is available when editing an existing asset. Only the selected image is read. Image content and guidance determine the cache key; changing the name or description requests a new refinement. Suggestions are saved only through the normal import/save action.

## Isolation

The backend implementation lives in `app/shot_workspace`; frontend components live in `features/shot-workspace`. Project authoring mode is persisted separately from production type. The normal Director Agent implementation is retained. Workspace writing uses bounded direct model calls and durable task receipts, including refresh recovery and cancellation.

Tests use synthetic images, generic objects and invented dialogue. Runtime data, personal projects and service configuration are not included.

The brief Save action lives inside the brief composer, beside Clear. The Prompt area offers Write prompt / Cancel and Write prompt & generate; successful writing saves its result automatically. The combined action starts video only after a successful write, retains the selected provider/size, and can resume its pending handoff after a page refresh.

Project size is saved per project and inherited by later shots, including Write prompt & generate. Without a saved size, the first shot's generated video seeds a matching preset; otherwise the default is the 480 tier. Previous-shot continuation always matches the source video's resolution. Selecting Standalone shot disables continuation; uploads are available only in uploaded-video mode.

The workspace AI model picker is in the header. The assistant uses an actionable Cancel button while Thinking and elapsed time remain separate status text. Each section retains its latest operation timing without a separate timing-history list.
