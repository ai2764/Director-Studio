## 修了什么

1. **观察结果不再压成一段描述。** 普通写作和尾帧续写都保留可见事实、未知项、冲突、原始来源。不可见/不确定属性不能同时声明一个确定值。模型推断始终标为 `model_observation`；引用了用户原话也不会变成“用户确认”。引用类型单独记录。
2. **一次有针对性的纠错。** 同一张图发现冲突时重看一次，与格式修复共用两次调用上限。仍未解决的争议从确定描述/对应事实移入 uncertainty，而不是无限重试。无人物、衣服或项目关键词黑名单。
3. **版本贯穿到真正提交的输入。** 图片字节、Picture 顺序、元数据、导演要求、shot 意图及最终 prompt 绑定凭证。生成前要求当前凭证；真正暂存的图片字节再次与审查快照比较。Job 保存该凭证和证据快照，便于追溯。
4. **失败草稿也需要版本。** repair key 纳入参考策略和当前观察证据，防止新的观察已经纠正，旧草稿却通过局部合并复活旧描述。
5. **只重看变化的图片。** 单图替换时测试从整包 18 次观察降为 10 次（首次 9 张 + 变化 1 张）；完整参考组仍参与导演判断。项目派生事实落盘不改 authored managed-run fingerprint。
6. **小边界。** 无效来源缓存必须重新观察；未知项合并保持 schema 有效；事实记录保留观察模型/提供方；数字属性无损转为文本，不因“人数=1”浪费一次修复。

## 关键裁决与代价

按作出顺序记录：

1. 本轮先完成参考事实链，不扩成 QC/自动重拍系统；代价是成片和重启问题仍待后续。
2. 按用户休息前的自主迭代授权执行已有设计，不等待额外审批；技术取舍事后报告。
3. 观察层与提交层作为一个整体验证、提交；代价是没有可单独使用的中间实现提交。
4. 只重新观察变化图片，保留整包决策；代价是依赖缓存键覆盖所有相关输入。
5. 旧 observation envelope 可读，新策略使旧缓存失效；代价是模型仍可能省略事实或未报告的冲突。
6. 数字值正规化、明确原文引用与冲突生命周期，不增加重试次数；代价是语义错误仍可能超过单次纠错能力。
7. 不把未报告的语义矛盾当作确定性校验能解决的问题；代价是模型误看仍可能进入 prompt。
8. 成片重复人物、声音质量不混入本阶段；代价是历史媒体缺陷不被此次代码修改修好。
9. 不用中途重启证明恢复能力；代价是 restart survival 没有新增验收证据。
10. 执行者评估并公开真实模型的失败，不把代码审查当模型验收；代价是小样本不能代表生产分布。
11. 暂留被忽略的测试/探针证据供复查，不立即清理；代价是少量本地磁盘占用。

## 工程思维 / 下一步

传统产品代码经常检查“请求是否合法”；agent 系统还要检查“这个决定基于哪一版证据”。本轮把 **输入 → 观察 → 决策/草稿 → prompt → job** 的来源和版本连起来，限制的是过期状态、虚假来源与无限重试，不是镜头、构图、表演的选择。

下一优先级是独立的成片验收闭环：job success 只表示渲染完成，不能等同于创作目标满足。先产出带具体画面/时间点证据的 QC 结果，再由 agent 决定保留、修订或向用户升级；失败次数和预算属于执行框架，创意修法仍交给模型。另开故障注入验收验证托管重启恢复，避免与视觉 QC 混成一次大改。
